¿Qué cambia respecto a una imagen normal?

❌ Imagen regular

  • Shell disponible (sh, bash)
  • Package manager activo (apk, apt)
  • Se ejecuta como root
  • Puertos privilegiados (80, 443)
  • ~23.1 MB (nginx alpine)
  • 84 vulnerabilidades conocidas

✅ Imagen hardened

  • Sin package manager
  • Se ejecuta como non-root
  • Puertos no privilegiados (8080)
  • ~4.8 MB (79% menos)
  • 1 vulnerabilidad conocida
  • Attestations firmadas (SBOM, provenance)

Ventajas clave

🔒 Superficie de ataque mínima

Sin shell ni package manager en runtime, un atacante que comprometa el contenedor no puede descargar herramientas, escalar privilegios ni moverse lateralmente.

👤 Non-root por defecto

Las DHI se ejecutan con un usuario sin privilegios. Si un proceso es comprometido, su impacto está limitado a lo que ese usuario puede hacer.

📦 Tamaño reducido

Menos binarios y librerías significa menos código que puede tener vulnerabilidades. Una imagen de 4.6 MB tiene mucho menos que auditar que una de 22.7 MB.

📋 Attestations y SBOM

Cada imagen incluye metadatos firmados: qué contiene (SBOM), cómo se construyó (provenance), y qué vulnerabilidades tiene. Verificable con ORAS.

🛡️ Socket Firewall (variantes -sfw-dev)

Protección de supply chain durante la instalación de dependencias. Detecta y bloquea paquetes maliciosos antes de que lleguen a tu imagen.

🏗️ Patrón multi-stage

Usa -dev para compilar (con shell y herramientas) y la imagen runtime limpia para producción. Solo lo necesario llega al contenedor final.

Pruébalo tú mismo

# Construir con imagen regular
docker build -f Dockerfile.regular -t web-regular .
docker run -p 8080:80 web-regular

# Construir con imagen hardened
docker build -f Dockerfile.hardened -t web-hardened .
docker run -p 8081:8080 web-hardened

# Comparar tamaño
docker images | grep web-

# Comparar vulnerabilidades
docker scout quickview web-regular
docker scout cves web-hardened --format sarif
